# 꿈 기록 수정 정책

Archive 화면의 확정 정책에 맞춰 제목·원문·감정을 수정한다. 날짜와 AI 생성 키워드는 수정 대상이 아니다.

## 요청과 저장

`PATCH /api/v1/dreams/{dreamId}`의 `revision`에는 최근 꿈 조회 응답의 revision을 전달한다.
필드를 생략하면 유지한다. 원문은 Unicode 코드포인트 기준 최대 500자이며 비어 있을 수 없다.
원문의 공백·줄바꿈은 그대로 저장한다.

제목을 새로 정하거나 변경할 때 최대 20 코드포인트를 허용한다. 이모지도 코드포인트로 센다.
`title:null`, `title:""`, Unicode 공백만 있는 제목은 null로 저장한다.
실제 내용이 있는 제목의 앞뒤 공백은 제거하지 않는다.
기존 20자를 초과하는 제목은 생략하거나 동일 값으로 재전달하면 유지한다.
DB VARCHAR(100)는 보존하여 과거 제목을 잘라내지 않는다.
존재하던 제목을 제거하면 수정 표시가 남아 이후 생성 제목으로 덮어쓰지 않는다. 이미 없는 제목을 비우는 요청은 무변경이다.

완료 후에도 기존 7종 중 중복 없이 1~2개로 감정을 수정할 수 있다. 동일 집합의 재전달은 무변경이며 순서는 무관하다.

#109부터 최초 선택과 감정 수정 요청 모두 최대 2개만 허용한다. 3개 이상·빈 배열·중복·null 요소는
기존 `DREAM_400_4`로 거절하고 원문·제목·감정·버전·기록 상태를 부분 저장하지 않는다.
최초 선택의 누락/null은 기존 필수값 검증, 잘못된 감정 문자열은 기존 JSON 형식 검증을 유지한다.

이전 정책으로 감정 3개가 저장된 기록과 분석·서사·세계관 스냅샷은 임의로 줄이거나 다시 생성하지 않는다.
기존 기록 조회와 감정을 생략한 원문/제목 수정은 기존 3개를 유지한다. 감정을 명시해서 수정하면
같은 3개를 재전달하더라도 새 1~2개 제한으로 검증하며, 순서를 기준으로 앞의 2개를 고르지 않는다.
프론트는 변경하지 않은 감정 필드를 PATCH에서 생략하고, 감정을 변경할 때 선택을 1~2개로 맞춘다.
요청 Swagger 배열에만 minItems=1/maxItems=2/uniqueItems=true를 표시하고 조회 응답에 상한을 추가하지 않는다.
DB 스키마·환경변수·기존 데이터 보정 작업은 필요 없다.
중복·빈 목록·null 등은 `DREAM_400_4`(400)이다. 이전 `DREAM_400_5`는 보존된 식별자이며 현재 정책에서는 발생하지 않는다.
복합 요청의 모든 필드를 검증한 뒤 변경하므로 잘못된 감정·제목과 함께 보낸 원문도 저장하지 않는다.
최초 선택에서는 기존 7종 감정을 중복 없이 1~2개 선택한다.

## 수정 버전과 AI 입력 버전

| 값 | 용도 | 증가하는 변경 |
| --- | --- | --- |
| Dream.revision | 수정·삭제·분석·서사화 요청 충돌 방지 | 실제 제목·원문·감정·작성 상태·수정 표시 변경 |
| Dream.sourceRevision | AI 입력 출처 비교 | 실제 원문·감정 변경과 최초 감정 선택 |
| Analysis.sourceRevision / observedRevision | 생성 시 입력 및 비교 기준 | 기존 분석 생성 과정 |
| Story.sourceRevision / resultRevision | 현재 시도 및 표시 중 성공 결과의 입력 기준 | 기존 서사화 생성 과정 |

두 버전의 수치는 같다고 가정하지 않는다. 요청에는 sourceRevision을 넣지 않는다.
분석 상태와 감사 updatedAt은 이전 #13 수정처럼 Dream.revision을 증가시키지 않는다.
#19 자동 제목 저장은 제목 변경이므로 revision이 증가할 수 있다. 분석 응답의 dreamRevision 또는 최신 꿈 조회 버전을 사용한다.
제목만 수정하거나 비우면 기존 분석·서사화가 `sourceChanged:false`를 유지한다.
수정이 허용된 초기 분석 중에는 제목을 바꾸어도 AI 입력이 같으면 결과를 저장한다.
다만 명시적 분석·서사 재생성, 활성 이미지·브리지·세계관 구성 작업 중에는 제목을 포함한 수정/삭제를 차단한다.
원문·감정을 바꾸면 기존 결과는 보존하며 `sourceChanged:true`로 표시한다.
생성 도중 원문·감정을 변경하거나 변경 후 복원해도 해당 시도의 새 결과는 SOURCE_CHANGED로 폐기한다.
최신 원문·감정의 분석과 서사는 `POST /api/v1/dreams/{dreamId}/generation/regenerate`에 최신 revision·generationVersion을 전달해 명시적으로 생성한다.
분석·서사가 모두 성공하면 키워드·장면·요소와 함께 교체하며 실패·롤백에는 이전 성공을 유지한다. [생성 계약](dream-generation-versioning.md)을 따른다.
기존 세계관의 고정 서사 버전은 바꾸지 않는다. 사용자가 선택한 세계관의 apply API로 대상과 앞뒤 연결만 반영한다. [세계관 계약](world-composition.md)을 따른다.

## 삭제 안내

꿈·감정·관련 분석·장면·요소·서사·성공 버전·개별 이미지 DB 기록과 브리지를 함께 영구 삭제한다.
통계와 최근 해석 대상에서도 제외한다. 이미지 파일은 마지막 성공 키의 정리 요청을 같은 DB 트랜잭션에 남긴다.
세계관의 선택·완성본 참조도 같은 트랜잭션에서 정리하며, 남은 꿈이 0~1개여도 폴더를 보존한다. 삭제 후 새 연결을 자동 생성하지 않는다.
세계관 전체 이미지는 유지하고 삭제 전 구성으로 생성됐음을 표시한다. 실제 파일 삭제는 [정리 워커](image-cleanup-worker.md)가 처리하므로 DB 삭제 성공을 물리 삭제 완료로 안내하지 않는다.

> 꿈 기록과 관련 분석·이야기·개별 이미지 기록은 영구 삭제되어 복구할 수 없습니다. 이미지 파일 정리는 별도 처리됩니다.

활성 생성 중에는 409다. [영구 삭제 계약](dream-deletion.md)의 외부 저장소·과거 데이터 한계를 참고한다.

## MySQL 적용

현재 배포는 [Flyway 배포 계약](database-migrations.md)을 따른다. 아래는 #17 도입 당시 수동 적용 이력이며 신규 배포 절차가 아니다.

기존 DB는 `src/main/resources/db/migrations/20261006-dream-edit-policy.sql`을 수동 실행한다.
새 DB는 갱신된 `schema-initial.sql`을 사용한다. 패키지 스크립트는 DB에 접속하지 않는다.
기존 레코드의 source_revision은 현재 revision으로 초기화하고, 기존 분석·서사화의 출처는 변경하지 않는다.
과거 제목만 수정했는지 원문을 수정했는지 판별할 이력이 없으므로 이미 오래된 결과는 그대로 표시할 수 있다.
초기화 이후 제목 변경부터 정확히 구분한다. 실패 후 SQL을 재실행해도 이미 초기화된 값을 덮어쓰지 않는다.
앱/AI 호출을 모두 중지하고 백업한 뒤 SQL을 적용하고, 새 코드로 함께 재시작한다.
DDL 자동 커밋으로 코드만 되돌린다고 스키마가 복구되지는 않는다.

## 회귀 검증

도메인: 제목 20/21 코드포인트, null/빈/Unicode 공백, 기존 긴 제목 보존,
감정 수정·동일 집합 재전달과 복합 요청 원자성, 입력 변경 후 복원, 초안→감정 선택의 버전 증가.
HTTP: 제목 삭제·경계값, 감정 변경의 영속화, 같은 값 재전달 및 이전 버전 거절.
원문·감정이 함께 변경되어도 sourceRevision은 수정 요청당 한 번만 증가한다. 실제 변경이 없는 요청은 edited·revision을 바꾸지 않는다.
분석/서사화: 제목 수정 전·중·후 결과 유지, 원문 변경 시 폐기/오래된 표시,
이전 optimistic revision 요청 거절, 기존 실패·재시도 회귀. 삭제 검증은 #48 계약에서 갱신했다.
