# 회원탈퇴 (#126)

## API와 프론트 흐름

- `DELETE /api/v1/users/me`: Bearer 인증. 닉네임 온보딩 전에도 가능. 본문·사용자 ID를 받지 않는다.
- 성공은 공통 `ApiResponse<Void>`의 200, Cache-Control: no-store. Refresh 쿠키도 제거한다.
- 모든 기기의 세션·토큰 이력을 제거하므로 기존 Access/Refresh는 다음 요청부터 401이다.
- `USER_503_1`: 기능 비활성/미준비. `USER_409_2`: 유료 잔액 환불 미접수. `USER_409_3`: 결제 승인 확인 필요.
- 프론트는 409_2에 환불 안내 모달을 표시한다. 서버는 사용자 잠금 안에서 잔액·접수 상태를 다시 판정한다.
- 유료 잔액이 없으면 즉시 탈퇴. 남은 유료 구매분에 대한 환불이 실제 접수됐다면 처리 완료를 기다리지 않는다.
- REQUESTING/UNKNOWN/PENDING 거래는 승인 확인을 위해 차단한다. READY(미사용 결제창)만으로는 막지 않는다.
- 미확정 결제는 기존 결제 운영 조회 절차로 거래 상태를 확인한다. 임의로 성공/실패를 추정하거나 타임아웃만으로 지우지 않는다.

`GET /api/v1/credits/balance`의 기존 필드(available/reserved/total/spendingBlocked)는 유지한다.
추가 필드는 paidAvailable/paidReserved/freeAvailable/freeReserved이다. PAYMENT만 유료이고
SIGNUP/ATTENDANCE/PROMOTION은 무료다. 지급 출처를 한 번에 SUM 집계한다.
예약 수량은 즉시 환불 가능한 수량을 뜻하지 않는다. 환불 금액은 구매별 계산으로 별도 구현한다.

## 범위와 후속 환불 기능

회원탈퇴 기능은 기본 비활성이다. 환불 신청 UI/API, 금액 계산, PG 환불 실행, 안내 경로는 후속 이슈다.
현재 기본 WithdrawalRefundPolicy는 유료 잔액을 승인하지 않는다.
후속 환불 서비스는 이 포트를 대체해 같은 사용자 잠금 안에서 실제 DB 접수 내역이
모든 남은 유료 구매분을 커버하는지 확인해야 한다. 클라이언트의 boolean이나
이메일 발송만으로 접수됐다고 처리하면 안 된다.
hasOpenRefunds는 보존기간 종료 시 미완료 접수 건의 삭제를 막아야 한다.
이 연결 전에는 유료 기능을 출시하지 않는다.

| 꿈/세계관 이미지 | 현재 키 및 진행 중 업로드 .png/.jpg 정리 대상 등록 후 이미지 행 삭제 |
| 비결제 계정의 크레딧 계정/원장/지급/예약/배분 | 벌크 삭제 |

| 주문·PG 거래·통보·크레딧 정산 | 개인정보 없는 사용자 PK 표식과 연결해 별도 접근 관리, 거래 기준 5년 |
| 가입 보상 중복 방지 | 카카오 계정 HMAC, 혜택 종류, 지급일만 별도 테이블 보관. 해당 혜택 운영 종료까지 |
| 카카오 원문 회원번호 | AES-GCM 암호화해 연결 해제 작업에만 보관. 성공/미시작 작업 취소 시 제거 |

사용자 PK 표식은 복구 가능한 사용자 프로필이 아니다. 거래 테이블의 행은
일반 사용자 API에서 접근할 수 없고 운영 정산 경로만 사용한다.
비결제 PK 표식도 후속 작업 완료 후 제거한다. 정리 워커가 비활성이거나
파일 삭제 실패로 HELD라면 파일 정리와 최소 표식 삭제가 지연되므로 반드시 운영 상태를 확인한다.

원본 변경과 후속 작업 등록은 한 트랜잭션이며 실패 시 함께 롤백한다.
대량 엔티티 조회·건별 DreamService.delete 반복을 사용하지 않는다.
쿼리 개수는 콘텐츠 건수와 무관하지만 실제 처리 행 수에 비례해 IO/잠금 시간은 증가한다.

## 재가입·카카오 연결 해제 경합

대기 중이며 한 번도 외부 호출하지 않은 연결 해제는 재가입 트랜잭션에서 취소한다.
새 앱 계정이 생긴 뒤 예전 탈퇴 건이 새 연결을 끊지 않도록 동일 HMAC 작업을 잠가 판정한다.
이미 외부 요청을 시작했거나 응답이 불확실한 경우에는 연결 해제의 확정 결과가 나올 때까지
OAuth 완료가 AUTH_503_1로 일시 실패한다. 재가입 정책상의 대기기간을 두는 것은 아니지만,
외부 API에 조건부 연결 해제가 없으므로 호출 중인 순간까지 무조건 새 계정을 발급할 수는 없다.
기한이 지난 PROCESSING은 재시도하며 요청의 세대 token이 다른 완료 응답은 무시한다.
Kakao 200 응답의 회원번호 일치 또는 400/-101(이미 연결 안 됨)만 완료로 확정한다.
타임아웃/인증/기타 오류는 성공으로 처리하지 않는다.

첫 가입 보상 지급과 HMAC 기록은 같은 트랜잭션이다. 적용 전 가입자는 탈퇴 시 기존 SIGNUP
지급 여부를 이관한다. 같은 카카오 계정 재가입은 닉네임 온보딩을 마쳐도 다시 지급하지 않는다.
카카오 앱의 회원번호 고정 설정이 전제다. 다른 카카오 계정을 같은 자연인으로 식별하지 않는다.
일반 사용자/마케팅 용도로 HMAC을 사용하지 않는다. 키 교체는 기존 비교값의 연속성을
보장하는 별도 마이그레이션이 필요하다. 운영 중 키를 임의로 바꾸면 중복 지급 방지가 깨진다.

## 설정·배포

먼저 V7__user_withdrawal.sql을 기존 마이그레이션 절차로 적용한다. 이미 적용된 V1~V6은 수정하지 않는다.

- MONGLE_WITHDRAWAL_ENABLED: 기본 false.
- MONGLE_WITHDRAWAL_IDENTITY_KEY: 독립된 32자 이상 비밀값. HMAC 비교 전용.
- MONGLE_WITHDRAWAL_ENCRYPTION_KEY: 위 값과 다른 독립된 32자 이상 비밀값. 작업 암호화 전용.
- KAKAO_ADMIN_KEY: 해당 서비스 앱의 어드민 키. 클라이언트 시크릿과 다르며 서버 비밀 저장소에서 주입한다.
- MONGLE_WITHDRAWAL_WORKER_ENABLED: 기본 false. 연결 해제·보존기간 종료 정리 활성화.
- MONGLE_WITHDRAWAL_POLL_INTERVAL: 기본 10s. 회당 연결 해제 5건, 보존 정리 5건.
- MONGLE_WITHDRAWAL_REQUEST_TIMEOUT: 기본 5s, 최대 30s.
- MONGLE_IMAGE_CLEANUP_ENABLED: 파일 정리 워커도 별도로 활성화하고 스토리지 권한을 검증한다.

기능 공개 전 키·어드민 권한·회원번호 고정·두 종류의 워커·정책 고지와 처리 근거를 준비한다.
신규 탈퇴 API 비활성화와 후속 작업 워커 활성화는 독립적이다. 탈퇴 API를 닫아도 이미
접수한 연결 해제·기록 파기는 계속 실행할 수 있다. 키가 설정돼 있으면 가입 보상 중복
방지도 유지한다. 이력이 있는 동안 키를 제거하면 안 되며, 키와 이력이 없는 초기 기본
비활성 상태에서는 기존 가입·로그인·닉네임·크레딧 동작을 유지한다.
민감 값·카카오 ID·암호문·환불 연락처를 로그/Swagger/사용자 응답에 넣지 않는다.
모니터링 대상은 social_unlink_tasks.state/attempt_count/next_run_at/failure_code,
image_cleanup_requests.status/failure_code와 users.retention_until이다.
민감 열을 전부 출력하는 select * 기반 운영 모니터는 사용하지 않는다.

## 보관 종료·파기

WithdrawalRetention은 만료 후보를 소량 조회한 뒤 사용자별 잠금 아래 재검증해 파기한다.
미완료 환불·카카오 해제·이미지 정리 건은 파기하지 않는다. 후속 작업 완료 전에는
민감한 프로필을 보존하지 않고 최소 PK/작업 정보만 유지한다.
초기 거래 만료일은 마지막 주문 변경 시점+5년이며 탈퇴일로 일괄 재시작하지 않는다.
탈퇴 후 검증된 결제 정산 통보/결과 처리 시 필요한 보관 기한을 연장한다.
불만/분쟁 접수 기능은 현재 없으며 도입 시 해당 기록을 별도 분리해 3년 보존해야 한다.
해당 가입 혜택의 운영 종료가 확정되면 내부 WithdrawalRetention.deleteEndedSignupBenefit()을 통해
비교 기록을 일괄 파기한다. 일반 HTTP API로 노출하지 않으며 새 혜택으로 임의 재사용하지 않는다.
가입 보상 식별 기록은 법정 거래 보존과 별개다. 목적·항목·기간·근거/필요성을
개인정보 처리방침에 반영하고, HMAC을 익명정보로 표시하지 않는다.

## 동의 기록 연동 (#128)

V8에서 문서별 동의 기록과 회원의 요약 상태를 추가합니다. 거래기록이 없는 탈퇴 계정의 동의는 삭제하고,
거래 관련 보존이 필요한 경우 정산 기록과 함께 보관한 후 WithdrawalRetention 만료 파기에서 제거합니다.
문서 버전 레지스트리는 개인정보 없는 본문 해시 자료이며 개인 동의 기록과 구분합니다.
동의 미완료만으로 탈퇴·금융 확인 경로를 막지 않습니다. [동의 저장·배포 계약](legal-consents.md)을 참고합니다.
