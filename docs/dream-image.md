# 꿈 이미지 생성 및 결과 보존 기반

## 범위와 연결 상태

완료된 최신 장면 분석과 이야기로 이미지 생성을 예약하고 결과를 보존한다. #56의 선택적 [OpenAI Provider](image-openai.md)와 #54의 선택적 S3 저장소를 제공하며 각각 기본 비활성이다. 모델·이미지 옵션은 운영 설정으로 공급해야 한다. 기본 생성기는 사용 불가 상태이고 신규 생성 요청에 503을 반환한다. Mock 이미지를 운영 API에서 반환하지 않는다. 개별 이미지 크레딧 예약·확정·해제는 #64에서 연결했다. 구매 결제와 공개 공유는 이 API의 책임이 아니다. [과금·복구 계약](credits.md)을 함께 따른다.

화풍 4종을 기본 허용 목록으로 제공하며 [이미지 생성 정책](image-generation-policy.md)을 따른다. `mongle.image.styles`, `mongle.image.moods`로 목록을 덮어쓸 수 있다. 키는 `[a-z][a-z0-9-]{0,49}`이고 중복을 허용하지 않는다. 스타일 목록이 비어 있으면 생성 불가다. 스타일은 필수, 분위기는 선택이며 null은 별도 분위기 선택이 없음을 뜻한다. 기본 화풍은 없으며 화풍 선택 전 생성 버튼을 비활성화한다.

## API

모든 API는 인증이 필요하고 응답에 `Cache-Control: no-store`를 설정한다. 이미지 생성은 온보딩 완료 사용자만 가능하다.

| Method | Path (`/api/v1` 기준) | 결과 |
| --- | --- | --- |
| GET | `/image-options` | 설정된 styles/moods 키 |
| POST | `/dreams/{dreamId}/image` | 생성·재사용·재시도; PROCESSING 202, COMPLETED/FAILED 200 |
| GET | `/dreams/{dreamId}/image` | 살아 있는 원문에 연결된 최신 이미지 메타데이터 |
| GET | `/images/{imageId}` | 소유자의 이미지 메타데이터; 꿈 삭제 후 404 |
| GET | `/images/{imageId}/download-url` | 소유자의 마지막 성공 파일용 5분 이내 HTTPS 임시 URL |

생성 본문: `revision`, `style`, 선택적 `mood`, 기본 false인 `regenerate`, 재생성 시 필수 `imageVersion`. `revision`은 꿈의 낙관적 잠금 버전이고 이미지의 `imageVersion`과 다르다. 최초 요청은 완료된 최신 분석과 COMPLETED 이야기가 필요하다. 다른 사용자의 꿈/이미지는 404로 처리한다.

분석당 하나의 현재 이미지 레코드를 사용한다. 같은 입력의 성공 결과는 재사용한다. 이야기 JSON 해시, 원문 입력 버전 `sourceRevision`, 옵션 중 하나가 달라지면 명시적 재생성이 필요하다. 재생성은 마지막 조회의 imageVersion을 보내야 한다. 실패 또는 임대 만료 시 상태를 조회한 후 다시 요청할 수 있다. 이전 성공 결과가 남아 있으면 일반 재시도는 마지막 시도의 스타일·분위기·원문 입력 버전·이야기 해시가 모두 같을 때만 허용한다. 입력이 달라졌거나 이전 성공 옵션으로 되돌리려면 `regenerate=true`와 최신 `imageVersion`을 전달해야 한다. 이전 성공 결과가 없는 최초 실패/만료는 허용된 옵션으로 일반 재시도할 수 있다. 활성 시도와 같은 입력의 중복 요청은 해당 PROCESSING 결과를 반환하고 Provider를 다시 호출하지 않는다. 입력이 다른 활성 요청에는 충돌을 반환한다.

생성기 계약은 `CompletableFuture<byte[]>`이며 HTTP 응답도 Spring MVC 비동기 처리로 완료한다.
새 생성 요청은 결과가 완료될 때 200, 같은 입력의 진행 중 요청은 바로 202를 반환한다.
응답을 기다리는 HTTP 연결은 남지만 요청 스레드나 대기용 풀 작업은 점유하지 않는다.
클라이언트의 연결 종료나 반환 Future 취소는 내부 업로드·DB 기록을 취소하지 않는다.
별도 영속 작업 큐는 없으며 서버 재시작 시 자동으로 이미지 모델을 재호출하지 않는다.

`MONGLE_IMAGE_MAX_CONCURRENT_CALLS`는 인스턴스별 진행 작업 한도이며 기본 4, 허용 범위는 1~64이다.
사용자당 생성 횟수나 스레드 수 제한이 아니라 외부 응답 대기·파일 검증·업로드·DB 기록을 합친 진행 작업 수다.
기본값 4는 Provider·저장 예산에 맞춘 부하 검증 전 시작값이며 OpenAI 제공자 연결 뒤 지연 시간·메모리·제공자 호출 제한을 측정해 조정한다.
설정 허용 최대값 64가 모든 서버에서 안전하다는 뜻은 아니다. 이미지 응답과 디코딩 결과가 메모리에 머무르므로
서버 메모리·파일 크기·완료 작업 지연을 측정한 뒤 늘린다.
기존 배포 환경에서 이 환경변수를 2로 지정했다면 코드 변경만으로 한도가 올라가지 않으므로 별도로 갱신해야 한다.
슬롯은 제공자 호출 전 확보하고 파일 검증·업로드·완료/실패 기록이 끝날 때 반환한다.
기존 성공 결과 및 같은 입력의 진행 결과를 재사용할 때는 슬롯을 요구하지 않는다.
새 작업의 한도 초과 또는 서버 종료 중에는 `503 / IMAGE_503_2`를 반환하고 예약 변경을 롤백한다.
Provider를 호출하거나 기존 성공 결과를 변경하지 않는다. 클라이언트는 잠시 후 명시적으로 재시도한다.
이 한도는 분석/서사화 풀과 별개이며 여러 인스턴스를 합친 한도나 서비스 토큰 과금을 보장하지 않는다.

동시에 16개가 외부 응답을 기다려도 대기용 스레드 작업 16개를 만들지 않는다.
제공자 완료 콜백에는 검증·JPA·스토리지를 실행하지 않는다. `image-result-*` 전용 풀은
`MONGLE_IMAGE_RESULT_THREADS`로 스레드 수를 지정하며 기본 2, 허용 범위는 1~8이다.
실제 스레드 수는 설정값과 진행 작업 한도 중 작은 값이고, 큐 용량은 진행 작업 한도와 같다.
완료 작업은 슬롯당 하나만 제출한다. 파일 디코딩과 동기 스토리지 I/O가 실행되는 동안은
이 제한된 스레드를 사용하며, 외부 이미지 응답을 기다리는 데 사용하지 않는다.
스토리지 put/delete/URL 발급의 실제 어댑터는 타임아웃을 설정해야 한다.
다운로드 URL 발급은 기존 동기 API를 유지한다.

외부 호출은 DB 트랜잭션 밖에서 실행하고 예약·완료·실패만 짧은 별도 트랜잭션에서 처리한다.
사용자 행 잠금을 기존 분석·이야기·꿈 편집과 공유한다. 시도 임대는 2분이다.
Provider 어댑터는 비동기 HTTP를 사용하고 전체 호출 타임아웃을 이보다 짧게 설정해야 한다.
블로킹 SDK를 `supplyAsync`로 감싸거나 이 서비스에서 `join/get`으로 기다리는 구현은 금지한다.
만료된 시도는 다음 명시적 요청으로 재시작할 수 있고 늦게 도착한 결과는 현재 결과를 덮어쓰지 않는다.
앱 종료 시 신규 작업을 막고 최대 5초만 완료를 기다린다. 이후 미완료 상태는 lease와 다음 요청으로 처리하며
유료 호출 성공 여부가 불명확할 수 있으므로 자동 재호출하지 않는다.

원문·감정 수정 후 최신 분석·이야기가 없으면 새 이미지 생성을 막고 이전 성공 결과를 보존한다. #43의 명시적 분석·서사 재생성으로 최신 입력의 성공 결과를 준비한다. 이미지 생성이 분석·서사를 자동으로 재생성하지 않는다.

## 보존·편집 정책

이미지는 `DreamAnalysis`에 연결한다. 유효한 이미지 생성 중에는 제목·원문·감정 수정 및 꿈 삭제를 409로 차단한다.
꿈 영구 삭제는 이미지 메타데이터도 제거하므로 단건/다운로드 URL 재발급과 늦은 완료/실패 저장은 404다.
확인 가능한 마지막 성공 파일 키는 삭제와 같은 트랜잭션에서 정리 요청으로 기록한다. 파일 정리는 [#50 워커](image-cleanup-worker.md)가 처리한다. 워커는 기본 비활성이며 S3 어댑터 설정과 운영 전제는 [S3 연동 문서](image-s3.md)를 따른다.
이미 발급된 서명 URL은 최대 5분 만료 전까지 유효할 수 있다. 만료된 작업이 뒤늦게 업로드하면 새 객체만 보상 삭제하고,
보상 실패는 `DISCARDED_UPLOAD` 정리 요청에 남긴다. 원본/메타데이터를 복원하지 않는다.
생성 중 원문 내용이 바뀌면 SOURCE_CHANGED, 이야기 JSON이 바뀌면 STORY_CHANGED로 실패하고 새 업로드를 폐기한다.
기존 배포의 FK 분리 데이터는 자동 일괄 삭제하지 않는다. `sourceDeleted` 필드는 이 과거 데이터와의 응답 호환을 위해 남긴다.

재생성 중이거나 실패한 경우 마지막 성공 파일은 보존한다. `style/mood`는 현재 시도, `resultStyle/resultMood/resultRevision`은 화면에 표시할 성공 파일의 입력이다. `hasPreviousResult=true`이면 이전 성공 파일을 표시할 수 있다. `sourceChanged/storyChanged`는 표시 가능한 마지막 결과가 현재 입력과 다른지 알려준다. 상태 PROCESSING/FAILED 자체가 파일 없음이라는 뜻은 아니다.

## Provider·스토리지 계약

`ImageGenerator.generate`는 비동기 결과를 반환하며 콜백 스레드에서 파일 저장이나 JPA를 호출하지 않는다.
네트워크 어댑터는 응답 크기를 제한하고 원문·이미지 바이트·외부 오류 본문을 로그에 남기지 않는다.
`ImageGenerator.Input`은 사용자/이미지/시도 식별자, `image-v1-story`, 옵션, 검증된 이야기 sections를 제공한다. 원문·이야기 전문의 별도 DB 스냅샷은 추가하지 않는다. SCENE과 AI_BRIDGE를 구분하고 Provider 어댑터에서 실제 프롬프트를 작성한다. 입력/출력의 toString은 이야기와 바이트를 노출하지 않는다. 기존 LLM Gateway의 텍스트 출력 계약에 이미지 바이트를 억지로 추가하지 않는다.

서버가 파일 헤더와 실제 디코딩을 검증한다. PNG/JPEG, 최대 10 MiB, 각 변 최대 8192, 총 픽셀 최대 16,777,216만 허용한다. MIME·확장자는 응답 문자열을 신뢰하지 않는다. 저장 경로는 서버 생성 `dream-images/{userId}/{imageId}/{attemptId}.png|.jpg`다. 버킷/컨테이너는 비공개여야 하며 `put`은 콘텐츠 유형도 적용해야 한다. URL이나 스토리지 키는 메타데이터 API에 노출하지 않는다.

스토리지 `put`은 해당 파일을 조회할 수 있는 상태에서 성공을 반환하고, `delete`는 객체가 이미 없어도 성공하는 멱등 동작으로 구현한다. 어댑터에서 실패 원인에 키나 서명 URL을 담더라도 API 경계는 이를 공통 예외 로그로 넘기지 않는다. 내부 서비스는 최초 실패와 보상 실패의 관계를 보존한다.

`temporaryUrl`은 HTTPS와 5분 이하 유효기간을 보장해야 한다. 사용자정보가 있는 URL, 만료된 URL, 더 긴 URL은 거절한다. 서명 URL/키/외부 예외 메시지를 로그에 남기지 않는다. 업로드 및 DB 저장 실패, 입력 변경, 뒤늦은 결과는 **해당 시도의 새 객체만** 삭제한다. 정리 실패 시 비공개 정리 요청을 기록하고 내용 없는 경고를 남긴다. 성공 객체를 잘못 삭제하지 않도록 스토리지의 미참조 객체 회수는 DB storage_key 참조와 생성 중 시도를 확인해야 한다. 경로 전체에 무조건 TTL을 적용해서는 안 된다.

DB와 외부 저장소는 원자적이지 않다. 프로세스 중단과 보상 삭제 실패에 대비한 실제 미참조 객체 회수 작업은 운영 스토리지 연결 시 필요하다. 재생성 성공 후 이전 파일은 즉시 삭제하지 않는다. 정리 요청 워커는 #50에서 구현했고 과거 모든 파일 키 이력·회수는 후속으로 구현한다. 이전 이미지들의 목록/이력 API가 구현된 것은 아니다.

## SQL 및 검증

현재 신규/기존 DB는 [Flyway 배포](database-migrations.md)로 V1+V2를 적용한다. 다음은 V1 이전 과거 안내다. 초기 스키마는 `db/schema-initial.sql`, 기존 MySQL 8 DB는 앞선 #19 SQL 적용 후 `db/migrations/20261006-dream-image.sql`을 수동 적용했다. `dream_images` 신규 테이블만 만든다. 기존에 같은 이름의 테이블이 있다면 실제 컬럼을 비교해야 하며 CREATE IF NOT EXISTS가 호환성을 검증하지는 않는다. 앱/AI 호출 중지 및 백업 상태에서 실행하고 Hibernate validate로 확인한다. 실행 스크립트는 운영 SQL을 자동 실행하지 않는다.

H2 MySQL 모드에서 전체 회귀 테스트와 초기 스키마 validate를 검증한다. 실제 MySQL 실행, 이미지 Provider 호출, 운영 S3 접속 및 PM 옵션은 검증되지 않았다. #54 S3 어댑터는 SDK 모의 전송과 로컬 HTTP로 검증한다. 이 항목이 준비되기 전에는 이미지 기능이 운영 완료된 것으로 취급하지 않는다.


## #46 생성 중 변경 보호

이미지·브리지 활성 작업의 수정·삭제 차단, 신규 예약 경합 및 프론트 상태 조회는
[꿈 변경 보호 계약](dream-generation-guards.md)을 따른다. 기존 성공 결과 조회·재사용은 신규 실행과 구분한다.

## 비동기 이미지 처리 통합 (#52)

#39의 비동기 호출/실행 자원에 #46 생성 보호, #48 영구 삭제, #50 파일 정리를 통합한다.
외부 응답 대기는 Future로 연결하고 검증·업로드·저장은 제한된 image-result 실행기에서 처리한다.
영속 접수 대기열은 별도 범위다. 실제 Provider/S3 어댑터는 #54/#56에 있고 크레딧 과금·중단 예약 복구는 #64에서 연결했다. 설정 활성화와 실환경 검증은 별도다.

비동기 생성·변경 보호·영구 삭제·파일 정리의 전체 계약과 두 실행 설정의 구분은 [#52 통합 문서](image-async-integration.md)를 참고한다.

## OpenAI Provider (#56)

실제 요청을 만드는 어댑터·설정·전체 본문 제한·오류 분류·실행 예산은 [OpenAI 연동 문서](image-openai.md)를 따른다.
기본 비활성이며 모델·크기·품질·화풍 매핑에는 #83 기본값이 있으며 운영 설정으로 덮어쓸 수 있다. 실제 유료 호출/계정 권한 검증은 별도다.

## 이미지 정책 (#83)

최초 생성 3크레딧, 꿈별 첫 재생성 성공 1회 무료, 이후 1크레딧을 적용한다. 무료 실패·만료는 횟수를 쓰지 않고 기존 성공 이미지를 유지한다. 수정은 AI를 자동 호출하거나 무료 이력을 초기화하지 않는다. 응답에 `freeRegenerationAvailable`, `nextRegenerationCost`를 추가한다. [세부 계약·프론트 연결·V2 배포](image-generation-policy.md)를 따른다.
