# 두 꿈 사이 연결 문장 생성 · 세계관 연동 계약 (#44)

## 적용 범위

`feat/44-world-bridge-generation`은 #43의 `feat/42-dream-generation-versioning`에서 분기한다.
#39의 이미지 비동기 변경이 없어도 구현·검증할 수 있다. 폴더·완성 세계관은 상준의 오케스트레이션에서 관리하고,
이번 변경은 두 성공 서사 버전 사이의 연결 문장 생성·보관·재사용을 제공한다. 별도 공개 HTTP API는 추가하지 않는다.

| 기능 | 이번 구현 |
| --- | --- |
| 날짜순 두 성공 서사 버전의 연결 | 구현 |
| 두 서사만 Gateway에 전달, WORLD_BRIDGE 로그 | 구현, 기존 공통 Gateway 사용 |
| 버전·프롬프트·요청 설정이 같은 연결 결과 재사용 | 구현, 사용자별 재사용 |
| 중복 요청·명시적 재시도·만료·늦은 응답 보호 | 구현 |
| 꿈 삭제 시 해당 꿈의 연결 결과 제거 | 구현, 다른 연결 유지·새 연결 자동 생성 없음 |
| 폴더 꿈 선택·세계관 조립·새 이야기 반영 팝업 | 후속 오케스트레이션/프론트 작업 |
| 크레딧 가격·차감·환급, 세계관 전체 이미지 | 이번 변경에 없음 |
| 분석·장면·개별 이미지 등 기존 그래프의 전체 영구 삭제 | 별도 후속 작업, 기존 보존/분리 동작은 남아 있음 |

## 호출 계약

인증된 사용자의 ID를 서버에서 정한 뒤 `BridgeService`를 호출한다. 프론트에서 전달한 사용자 ID를 사용하지 않는다.

```java
bridgeService.generate(userId, new BridgeRequest(firstStoryVersionId, secondStoryVersionId));
bridgeService.get(userId, bridgeId);
bridgeService.retry(userId, bridgeId, lastResponse.jobVersion());
```

`generate/retry`는 `CompletableFuture<BridgeResponse>`를 반환한다. 세계관 오케스트레이션은 블로킹 대기 대신
완료 결과를 조립 단계에 전달하고, 처리 중이면 조회 가능한 작업 ID를 프론트에 전달한다.
폴더의 꿈 선택·추가·제외·정렬·일반 조회·원문 수정만으로 이 메서드를 호출하지 않는다.
사용자의 세계관 만들기/새 이야기 반영/연결 복구 요청이 있을 때 호출한다.

- 요청에는 **두 `StoryResultVersion.id`**를 넣는다. 변경되는 `DreamStory.version`이나 꿈 ID가 아니다.
- 두 버전은 현재 존재하는 서로 다른 완료 꿈의 것이고, 같은 사용자 소유여야 한다.
- `dreamedAt`이 오래된 꿈을 before로 정규화한다. 체크 순서는 무관하다. 하루 한 꿈 정책으로 날짜 동률은 없다.
- 수정 전 성공 버전도 선택 가능하다. 살아 있는 원본이 수정되거나 새 버전이 생겨도 선택한 본문은 바뀌지 않는다.
- 세계관에는 성공한 `bridgeId`와 양쪽 `storyVersionId`를 고정 참조한다. PROCESSING/FAILED 결과를 확정 작품에 넣지 않는다.
- `jobVersion`은 재시도 경합 검사용이다. 성공 연결의 내용 버전이나 세계관 순서로 사용하지 않는다.

## 재사용·재시도·설정

저장 키는 `(userId, beforeVersionId, afterVersionId, promptVersion, SHA-256(settingsJson))`이다.
같은 키를 재요청하면 완료 결과는 즉시 반환하고, 처리·실패·만료 결과도 상태만 반환한다. 자동으로 다시 과금될
호출을 만들지 않는다. 서로 다른 폴더도 같은 소유자의 같은 두 버전을 사용하면 한 결과를 공유한다.
다른 사용자끼리 본문을 공유하지 않는다.

실패/만료 후에는 최신 응답의 `jobVersion`으로 `retry`를 명시적으로 요청한다. 진행 중/성공한 작업의 재시도는
기존 결과를 반환한다. 실패한 작업의 오래된 버전으로 재시도하면 충돌이다. 성공 결과를 덮어쓰는 강제 재생성은 제공하지 않는다.
새 서사 버전이나 프롬프트/설정 변경은 다른 재사용 키로 생성한다.

설정 스냅샷에는 제공자, 요청 모델, 출력 토큰 상한, 추론 강도, JSON 출력 형식을 저장한다.
API 키와 실제 응답 모델명은 저장/추정하지 않는다. 현재 공통 텍스트 Gateway는 LINER이고 이미지 제공자 선택과는 별개다.
실패한 작업의 저장 설정과 현재 설정이 다르면 `retry`를 거절한다. `generate`로 새 키를 요청해야 한다.
모델·출력 정책을 바꾸면 새 설정/프롬프트 버전을 사용해 캐시 출처를 구분한다.

## 생성 입력·출력

`world-bridge-v1`은 날짜순 **앞 이야기 본문·뒤 이야기 본문만** 사용한다. 꿈 원문, 내부 ID, 다른 꿈, 다른 연결,
세계관 전체 내용은 메시지에 포함하지 않는다. 한 꿈 안의 SCENE/AI_BRIDGE 섹션은 저장된 순서대로 합친다.
한 꿈 안의 AI_BRIDGE 섹션과 이번 WORLD_BRIDGE는 서로 다른 기능이다.

프롬프트는 두 이야기 외의 사건·인물·감정·인과를 만들지 않도록 지시한다. 관계가 부족하면 중립적인 장면 전환을 사용한다.
한국어 1인칭 관찰 시점·과거형·차분한 문체를 사용해 story-v2와 맞춘다.
출력은 `{ "content": "연결 문장" }`만 허용하며 1~3문장, 최대 500 Unicode 코드 포인트다.
서버는 JSON 구조·중복 키·추가 키·빈 내용·길이·제어 문자를 검사한다.
내용이 두 꿈에만 근거하는지와 문체 품질까지 규칙 검사로 보장할 수는 없으므로 실제 모델 샘플 검증이 필요하다.

## 트랜잭션·경합

예약/완료/실패/재시도는 기존 꿈 수정·삭제와 동일하게 사용자 행을 먼저 잠근다. DB 유니크 키로 중복 저장도 막는다.
예약 트랜잭션을 끝낸 뒤 외부 AI를 호출하고, 검증·저장은 제한된 결과 풀에서 별도 트랜잭션으로 수행한다.
분석·서사와 동일한 `mongle.ai.dream.max-concurrent-calls` 한도를 공유한다. 기본값을 늘리거나 이미지 한도를 변경하지 않는다.
호출·완료 큐가 차면 `CAPACITY_EXCEEDED`로 저장하고 외부 호출을 보내지 않는다.

시도마다 새 UUID와 2분 lease를 발급한다. 만료 상태 조회는 FAILED/ATTEMPT_EXPIRED를 반환한다.
만료 또는 교체된 시도의 늦은 응답은 성공으로 게시하지 않는다. 재시도는 같은 저장 행에 새 시도 ID를 발급한다.
HTTP/호출자 Future 취소 후에도 완료 저장과 슬롯 반환은 계속된다.
출력 형식 오류는 INVALID_OUTPUT, 통신 실패는 CALL_FAILED로 보관한다.
완료 저장 실패 시 본문/성공 상태를 롤백하고 별도 실패 트랜잭션에서 PERSISTENCE_FAILED를 기록한다.
앱 종료 등으로 실패 상태 저장도 불가능하면 lease 만료 후 사용자가 명시적으로 재시도한다.

## 세계관 부분 갱신과 삭제

예: A(v1) → AB → B(v1) → BC → C(v1).

- B(v2)가 생성되어도 기존 작품은 그대로다. 사용자가 반영할 세계관을 고르면 B(v2)로 교체할 후보를 만든다.
- A(v1)-B(v2), B(v2)-C(v1) 두 연결을 요청한다. 성공한 후보를 모두 확보한 뒤 세계관 조립 결과를 원자적으로 교체한다.
- 다른 이야기와 다른 연결은 유지한다. 같은 새 버전/쌍을 다른 세계관에 반영할 때 이미 성공한 연결을 재사용한다.
- 연결 생성 도중 폴더 선택/세계관 구성이 달라지면 오케스트레이션의 구성 revision으로 반영 충돌을 검사해야 한다.
  브리지 성공 자체가 현재 세계관의 자동 변경을 의미하지 않는다.

B를 영구 삭제하면 B에 관한 모든 브리지 행을 제거하고 성공 서사 버전/입력 스냅샷 삭제를 이어서 수행한다.
진행 중 연결 호출은 실제 제공자 통신을 취소하지 않지만, 늦은 응답이 삭제된 결과 행을 다시 만들지는 못한다.
오케스트레이션은 완성 작품에서 B 서사·AB·BC를 제거해 A C로 남기며 A-C를 자동 생성하지 않는다.
기존 A/C 서사와 다른 연결은 그대로다. 별도 연결 복구 요청을 받은 경우에만 A-C를 생성한다.

후속 세계관 참조 테이블을 추가할 때는 삭제 트랜잭션에서 해당 서사/브리지 참조를 먼저 제거하거나
참조 FK의 ON DELETE CASCADE로 **작품 구성 참조만** 제거해야 한다. 세계관 폴더나 다른 꿈까지 cascade하지 않는다.
지금은 폴더/완성 작품 저장 테이블이 없으므로 이번 브리지 삭제만으로 전체 세계관 삭제 정책이 완성된 것은 아니다.

삭제 확인 문구는 기존 합의대로 안내한다.

> 꿈 기록과 관련 분석·이야기·개별 이미지는 영구 삭제됩니다. 세계관에서 해당 이야기와 연결 문장도 제거됩니다.
> 기존 세계관 전체 이미지는 유지되며, 삭제한 꿈에서 유래한 표현이 남아 있을 수 있습니다.

위 문구의 전체 범위는 후속 전체 삭제 연동까지 구현한 뒤 적용한다. 세계관 전체 이미지 재생성/잔여 꿈 0~1개 유지 정책도
오케스트레이션에서 구현한다. 최소 두 꿈으로 세계관을 최초 생성하며 최대 꿈 수와 크레딧 정책은 그 작업에서 확정한다.

## DB 적용

새 DB는 `schema-initial.sql`을 사용한다. 기존 DB는 #43의 서사 성공 버전 및 생성 스냅샷 마이그레이션을 적용한 뒤
앱/AI 작업을 중지하고 백업 후 `db/migrations/20261011-world-bridge-results.sql`을 수동 실행한다.
앱이 SQL을 자동 실행하지 않는다. 테이블 생성은 재실행 가능하지만 이미 존재하는 잘못된 테이블을 자동 교정하지 않는다.
배포 전에 스키마/인덱스/FK를 확인한다. 행을 지울 때 공유 브리지에 대한 모든 작품 참조가 같이 처리되는지 검증한다.
롤백 시 새 테이블을 유지해도 구버전 앱에는 영향이 없다. 브리지 행이 존재한 채 #43 이전으로 코드를 되돌려
꿈/성공 버전을 삭제하면 FK가 걸리므로 쓰기 기능을 중지하고 의존 데이터를 먼저 검토해야 한다.

## 검증 범위

모의 Gateway 기반 테스트는 실제 AI 비용을 발생시키지 않는다. 날짜 정규화·소유권·DB 유니크 키·설정별 재사용,
원문 수정 중 고정 출처, 동시 중복·명시적 재시도·만료/교체 응답, 취소 후 저장, 호출 한도,
저장 롤백, 삭제 시 관련 연결만 제거, H2 MySQL 모드의 초기 DDL/JPA 및 마이그레이션 재실행을 검증한다.
실제 운영 MySQL 적용과 제공자의 문체/사실 출처 품질은 별도 배포·샘플 검증 대상이다.
