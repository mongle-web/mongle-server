# 이미지·브리지 생성 중 꿈 변경 보호 (#46)

## 범위와 선행 브랜치

#45의 feat/44-world-bridge-generation(9d885b6)을 기반으로 한다. #39 이미지 비동기 PR이 없어도 적용한다.
폴더·세계관 조립·전체 이미지·크레딧·전체 영구 삭제·운영 Provider/스토리지는 별도 범위다.

## 변경·예약 계약

| 작업 | 이미지/브리지 활성 상태 | 처리 |
| --- | --- | --- |
| 관련 꿈의 제목·원문·감정 수정, 삭제 | 하나라도 진행 중 | 409 DREAM_409_4 |
| 다른 꿈의 수정·삭제 | 관련 작업 없음 | 기존 검증 후 허용 |
| 분석·서사 신규 생성/명시적 재생성/실패 재시도 | 관련 파생 작업 진행 중 | 신규 실행은 409 |
| 이미지·브리지 신규 예약/실패 재시도 | 관련 분석·서사 재생성 진행 중 | 신규 실행은 409 |
| 기존 성공 결과 조회·동일 진행 요청 재사용 | 진행 여부와 별개 | 기존 결과 반환, 새 호출 없음 |
| 이미지와 브리지의 동시 생성 | 서로 고정 성공 서사를 사용 | 허용. 서로를 불필요하게 직렬화하지 않음 |

차단은 사용자 전체가 아닌 해당 꿈에 한정한다. 브리지는 앞/뒤 두 꿈 모두 보호한다.
같은 꿈이 여러 활성 브리지에 사용되면 모든 관련 작업이 종료·만료될 때까지 해당 꿈은 차단한다.
기존 #43의 분석·서사 재생성 보호는 유지하며 최초 자동 분석 중 입력 변경 처리 계약은 바꾸지 않는다.

변경과 신규 작업 예약은 기존처럼 사용자 행을 먼저 잠근 트랜잭션에서 검사한다.
작업을 기록한 뒤 외부 호출 전에 트랜잭션을 끝내므로 AI 응답 대기 중 DB 잠금이나 대기 스레드를 점유하지 않는다.
재사용 판정을 신규 실행 차단보다 먼저 수행한다. 조회·재전송이 새로운 AI 호출을 만들지 않도록 한다.
같은 입력이어도 명시적 이미지 재생성은 기존 캐시 조회와 구분하고 신규 작업의 보호 조건을 검사한다.

## 변경 가능 상태 API

GET /api/v1/dreams/{dreamId}/mutation-status

인증된 소유자의 현재 상태만 반환한다. 타인/없는 꿈은 동일한 404, 미인증은 401.
응답은 기존 ApiResponse.data 안의 다음 구조이며 Cache-Control: no-store다.

```json
{"mutable":false,"blockingTasks":["IMAGE","WORLD_BRIDGE"]}
```

blockingTasks는 ANALYSIS_STORY, IMAGE, WORLD_BRIDGE 순서로 중복 없이 반환한다.
차단이 없으면 mutable=true, blockingTasks=[]다.
프론트는 mutable=false일 때 수정·삭제 버튼을 비활성화하고 작업 종류에 맞는 안내를 표시한다.
상태 조회는 잠금 예약이 아니다. 화면 조회 후 새 작업이 시작될 수 있으므로 서버는 실제 변경 시 다시 검사한다.
409가 오면 입력을 보존하고 상태를 다시 조회해 완료/실패 뒤 최신 revision으로 재시도한다.
별도 목록 전체의 상태 필드나 폴더 상위 작업 상태는 이번 API에 추가하지 않는다.

## 만료·실패·재시작

이미지·브리지는 PROCESSING이고 leaseUntil이 현재 시각보다 뒤인 작업만 활성으로 센다.
완료/실패 또는 lease 만료 뒤에는 해당 파생 작업 때문에 꿈 변경을 계속 차단하지 않는다.
조회가 만료된 작업을 자동 재실행하거나 성공으로 바꾸지는 않는다.

만료 후 늦은 완료는 기존 완료 트랜잭션의 lease/시도 ID 검사에서 실패 처리한다.
이미지는 source/story 변경 검사와 새 업로드 보상 정리도 유지한다.
명시적 재시도는 새 시도 ID를 발급해 이전 응답이 새 성공을 덮어쓰지 못하게 한다.
서버 재시작 후 파생 작업의 유효기간이 끝나면 동일 계약을 적용한다. 유료 호출을 자동 재전송하지 않는다.

#43 영속 분석·서사 재생성 작업의 QUEUED/PROCESSING 보호·워커 복구 정책은 유지한다.
해당 작업은 파생 작업 lease 만료와 별개다. 만료된 파생 작업만으로 재생성의 보호를 해제하지 않는다.

## 조회·DB

이미지는 소유자·분석의 원본 꿈·상태·유효기간으로 존재 여부만 확인한다.
브리지는 소유자·앞/뒤 꿈·상태·유효기간으로 존재 여부만 확인한다.
기존 분석 원본 관계/이미지 analysis_id UNIQUE와 브리지 before_dream_id/after_dream_id 인덱스를 사용한다.
새 컬럼·테이블·인덱스가 없어 초기 SQL이나 기존 DB 마이그레이션은 추가하지 않는다.
실제 MySQL 쿼리 계획/운영 데이터 규모의 부하 검증은 별도다.

## 향후 세계관 연동

개별 브리지 생성이 끝나고 다음 브리지를 예약하기 전에는 활성 브리지가 없을 수 있다.
따라서 이번 보호만으로 전체 세계관 조립 수명 전체가 보호되는 것은 아니다.
세계관 상위 작업에서는 후보 구성 revision 및 사용하는 꿈의 보호 범위를 별도로 관리해야 한다.
