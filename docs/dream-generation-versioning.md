# #42 꿈 입력·생성 버전과 명시적 재생성

## 구현 범위

기준 develop: `527430224250ad1b3c16971bdbd1e8667195a4c3` (#41 포함). #39 변경은 포함하지 않는다.

- 날짜는 불변이고 사용자별 날짜 하나만 기록한다. 제목·원문·선택 감정은 수정할 수 있다.
- 제목만 바꾸거나 동일 원문/감정을 다시 저장하면 sourceRevision은 증가하지 않는다.
- 실제 원문/감정 변경은 sourceRevision을 증가시키지만 AI를 호출하지 않는다.
- 기존 결과는 유지한다. analysisSourceChanged/sourceChanged로 수정 전 결과를 표시한다.
- 명시적 재생성에서 분석과 서사가 모두 성공해야 표시 결과·장면·요소·키워드를 함께 교체한다.
- 실패/잘못된 출력/저장 실패에서는 이전 성공을 유지한다. 성공 버전은 추가하지 않는다.
- 최초 기록 완료 시 기존 자동 생성은 유지한다. 최초 생성은 기존처럼 분석 → 서사 순서로 공개한다.
  반면 `/regenerate`로 요청한 작업은 이전 성공이 없어도 분석·서사 전체 성공 전까지 공개하지 않는다.
- 개별 이미지는 자동 생성하거나 변경하지 않는다. 이미지 재생성은 별도 API다.

## API와 버전

| 값 | 의미 |
| --- | --- |
| revision | 꿈 수정 충돌 검사. 원문·감정·제목 수정에 사용 |
| sourceRevision | 실제 AI 입력 버전. 상태 변경이나 제목 수정과 무관 |
| analysisResultRevision / 분석 resultRevision | 현재 표시하는 성공 분석의 입력 버전. 없으면 null |
| story resultRevision | 현재 표시하는 성공 서사의 입력 버전 |
| generation.generationVersion | 생성 작업 행 버전. 새로운 명시적 재생성의 중복 방지에 사용 |
| resultVersionId / versionId | 성공 스냅샷 ID. 세계관에서 선택한 서사 버전을 고정할 때 사용 |

`GET /api/v1/dreams/{id}` 및 Archive 카드/상세의 `generation`에 상태·단계·실패 코드·버전을 제공한다.
기존 데이터에 작업 행이 없으면 generation=null이다. 이 경우 첫 재생성 요청에 generationVersion=0을 사용한다.
성공 버전 ID는 기존 서사 단건 API 및 버전 목록 API에서 조회한다. storyVersion은 성공 버전 ID가 아니다.

```http
POST /api/v1/dreams/{id}/generation/regenerate
Authorization: Bearer ...
Content-Type: application/json

{"revision": 3, "generationVersion": 8}
```

- 두 버전 값은 마지막 조회 값을 전달한다. non-null, 0 이상이어야 한다.
- 202 Accepted + Cache-Control: no-store. 최신 원문과 선택 감정으로 작업을 예약한다.
- 이미 같은 입력 작업이 예약/실행 중이면 기존 작업을 반환하고 AI 호출을 추가하지 않는다.
- 완료된 요청의 오래된 버전 재전송은 409다. 완료 후 새로 생성하려면 최신 버전을 다시 조회한다.
- 타인/없는 꿈은 404, 미완료 기록은 409, 미온보딩 사용자는 기존 온보딩 오류다.
- 생성 상태 조회는 `GET /api/v1/dreams/{id}/generation`이다.
- 실패한 같은 입력 작업의 재시도는 기존 `POST .../generation/retry`에 `{ "revision": ... }`를 보낸다.
  분석 성공·서사 실패면 임시 분석을 재사용해 서사만 재시도한다. 원문이 다시 바뀌었다면 retry가 아닌 regenerate를 사용한다.
- 통합 재생성을 요청한 뒤에는 개별 분석/서사 생성 API가 해당 작업을 재시작하지 않는다(409).
  통합 retry/regenerate를 사용해 작업 상태와 공개 시점을 일치시킨다.

## 저장·경합

분석 임시 JSON은 새 서사의 입력에만 사용한다. 조회와 통계는 기존 성공 분석을 읽는다.
서사 출력 검증 후 성공 스냅샷 추가, 현재 서사 교체, 분석/장면/요소/키워드 교체를 한 DB 트랜잭션에서 확정한다.
API 키·인증 정보·민감한 원문을 운영 로그나 settings에 기록하지 않는다.

성공 스냅샷에는 생성 당시 원문·선택 감정·분석 JSON·서사 JSON·각 프롬프트 버전과 요청 설정을 보존한다.
설정은 현재 LINER 어댑터가 실제 요청에 사용하는 값이다. 응답 모델명/사용량/비용은 기존 Gateway 감사 로그의 책임이며
요청 모델을 응답 모델로 추정하지 않는다. 제공자를 교체하면 설정 캡처 어댑터도 함께 변경해야 한다.
수정·재생성으로 이전 스냅샷을 업데이트하지 않는다. 동일 입력을 명시적으로 재생성한 성공도 새 ID를 발급한다.

사용자 → 작업 잠금 순서를 유지하고 외부 호출은 트랜잭션 밖에서 수행한다.
명시적 재생성 예약부터 전체 작업 완료/실패까지 수정·삭제를 409 `DREAM_409_4`로 차단한다.
DB 장애/재시작으로 작업이 남으면 기존 lease 복구·명시적 retry 계약을 사용한다. 만료만으로 입력을 변경해
실행 중인 작업을 무효화하지 않는다. 이전 시도 ID·입력 버전·lease·작업 토큰으로 늦은 완료를 차단한다.
제목만 수정하려고 해도 재생성 중에는 차단한다. 새 응답을 받은 후 최신 revision으로 다시 저장한다.

## 화면 표시와 통계

1. 수정 전 성공 결과가 있고 sourceChanged=true면 “수정 전 기록으로 생성된 결과” 안내를 표시한다.
2. 재생성 요청 중에는 기존 성공을 보여주고 진행 상태를 별도로 표시하며 수정/삭제 버튼을 비활성화한다.
3. 실패하면 기존 성공 + 실패 안내 + 재시도 버튼을 보여준다. 새 분석만 성공한 상태를 새 완료 결과로 표시하지 않는다.
4. 성공 후 상세/Archive/서사 버전을 다시 조회한다. 세계관은 자동 변경하지 않는다.
   향후 세계관이 저장한 versionId와 최신 성공 ID가 다르면 사용자가 반영할 세계관을 선택하게 한다.

키워드 통계·최근 분석 대상은 현재 공개 성공 분석만 사용한다. 재생성 중/실패에도 이전 성공을 한 번 집계하고,
새 성공 확정 시 장면/요소를 교체한다. 보존된 과거 스냅샷을 중복 집계하지 않는다.
감정 통계는 현재 기록에 사용자가 선택한 감정으로 집계하므로 감정 수정 즉시 반영된다.
Archive는 생성 작업도 한 번에 조회하며 카드 수에 따른 추가 쿼리나 AI 호출을 하지 않는다.

## DB 전환

새 DB는 `schema-initial.sql`을 사용한다. 기존 DB에서는 앱과 워커를 중지하고 백업 후 다음 순서로 수동 실행한다.

1. `20261010-dream-story-versions.sql`
2. `20261010-dream-generation-versioning.sql`
3. 새 앱을 시작하고 스키마/조회/생성/재시도를 확인한다.

기존 마지막 성공 서사를 legacy 버전으로 옮기며 기존 성공 분석의 observedRevision을 resultRevision으로 보존한다.
현재 원문을 과거 입력으로 추정하지 않는다. 기존 출처/설정이 없으면 null이다.
이미 덮어쓴 과거 결과는 복원하지 못한다. DDL은 자동 커밋되므로 운영 DB 리허설과 백업이 필요하다.
컬럼별 INFORMATION_SCHEMA 검사와 legacy 삽입 조건으로 재실행 가능하게 구성했다.
이번 자동 테스트는 H2 MySQL 모드의 신규 스키마/JPA 검증과 변환한 컬럼 DDL·백필·재실행 검증이다.
MySQL 8 프로시저 원문 실행, 실제 AI 문체/품질, 실제 외부 과금은 별도 운영 검증 대상이다.

## 후속 범위 — 아직 완료로 안내하지 않을 것

- 세계관 폴더 선택 목록/완성 작품 분리, 날짜순 연결, 앞뒤 두 버전만 사용하는 연결 문장, 부분 반영 팝업/API.
- 꿈 삭제 시 모든 분석·장면·요소·서사·개별 이미지/통계 및 세계관 부분 제거, 전체 세계관 이미지 유지 정책.
  현재 develop의 기존 삭제 보존 동작을 전면 교체하지 않았다. 다만 이번에 추가한 원문/감정 스냅샷과 성공 버전은 삭제한다.
- 프론트엔드 UI 구현, 크레딧 차감/환불/원장 정책. 이 API는 과금하지 않으므로 유료 정책 확정 전 무제한 재생성 UI를 출시하지 않는다.
- #39 이미지 비동기 작업 및 이미지 생성 중 삭제 계약 통합.

후속 삭제 정책을 적용할 때 세계관 참조를 먼저 정리하고 분석/서사/이미지 저장 구조와 스냅샷을 함께 제거한다.
세계관 버전 참조에는 영구 스냅샷 ID를 사용하되, 꿈 영구 삭제보다 우선해서 스냅샷을 영구 보존하지 않는다.
